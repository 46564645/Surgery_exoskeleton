# MuJoCo 仿真子项目 — Agent 工作约定

本文件适用于 `firmware/Exoskeleton_F446/sim/mujoco_arm/` 及其下所有文件。它在根目录 [AGENTS.md](../../../../AGENTS.md) 的基础上补充仿真专用规则；两者冲突时，以用户最新明确要求为准，其次本文件，其余沿用根 AGENTS。计划与进度见 [development_schedule.md 1.2–1.3节](<../../../../Main_ project/docs/development_schedule.md>)。

## 0. 目标

1. **在仿真中印证实体程序**：把固件里真实运行的控制代码（`App/control`、`s5_site.c` 配置）接入 MuJoCo，看它在“桌面固定外骨骼 + 人臂”模型上是否确实减少人臂需要出的力。
2. **在仿真中优化程序**：以后修改控制逻辑或参数，先在仿真里测试、对比、迭代，**不需要每次都上实机**。只有准备把新镜像真正刷到硬件运行时，才按根 AGENTS 4.4 做一次有界台架窗口。
3. 仿真结论都标“模型假设下”，不等于实物省力或人体安全。

## 1. 复用优先顺序（用户 2026-10-26 明确要求）

写任何仿真代码前，按以下顺序找可以照搬的东西，前一级能用就不往下找：

1. **本项目现有实现**：用户 Fusion 外骨骼包 `model/orthoease/`（外形、运动链、绑定点）；固件 `App/control/*.c`、`App/application/s5_site.c` 与 CMake 选项、`tests/run_host_tests.py` 的 MSVC 编译方式、`tests/host` 的桩、`tests/live_monitor` 的出图与 CSV 格式。仿真必须调用这些原代码，不在 Python 里重写一份控制算法。
2. **ExoKit**（`Open-source projects/ExoKit-main`）：关节/手臂/动作/条件/反应的划分、Amplify 等动作逻辑。
3. **参考项目**：[开源借鉴索引](<../../../../Open-source projects/开源项目借鉴索引表.md>)第 33 行（MuJoCo、myo_sim 肘外骨骼模型、MyoSuite `myoarm_relocate.xml` 桌子场景、MyoAssist/assist_sim、rehyb_mujoco）及其他对应行。
4. **网上开源项目与经验帖**：GitHub/Gitee 等仓库、MuJoCo 官方文档与论坛、技术博客。

以上都不合适时，先向用户说明查过什么、为什么不能用，再自行编写（沿用根 AGENTS 2.1 自主实现规则）。写代码前简短说明本次照搬了哪一级的哪个文件/函数，未读源码不能声称已参考。

## 2. 回复格式

默认中文，沿用根 AGENTS 第 1 节：做了什么 / 有什么影响（含实际验证结果，没跑就说没跑）/ 待确认的事（没有写“无”）/ 下一步 / 名词通俗解释。简单问答不套格式。

## 3. 编码准则（照抄根 AGENTS 第 2 节）

| 准则 |
|---|
| 查清接口，不臆造接口 |
| 明确目标，不含糊执行 |
| 尊重事实，不猜测业务 |
| 复用现有，不重复造轮子 |
| 适度验证，不虚报通过 |
| 遵循分层，不旁路控制 |
| 诚实说明，不假装理解 |
| 小步修改，不盲目重构 |

- 沿用现有命名和格式；Python 遵循 PEP 8，C 桥接沿用固件风格，接口用明确宽度类型。
- 单位写清：角度 rad、角速度 rad/s、力矩 N·m、电流 A；原始值只在边界换算。
- **参数集中**：物理参数只放 `model/params.json`（每项注明来源与状态：实测/粗估/估计/假设）；控制参数只来自固件 `s5_site.c` 与编译选项，仿真里不另写一份数值。
- 不加没有实际需求的抽象层、兼容分支和重复日志。

## 4. AI 辅助开发（照抄根 AGENTS 2.1）

- 需求和约束先明确，再写代码。
- 遇到稍复杂的问题先向用户报告现象和思路；**未查明根本原因前禁止改代码**，不“随便改一行试试”。
- 关键逻辑可解释、模块解耦：模型生成、传感器/执行器模拟、控制桥接、人体控制器、实验运行、指标、出图分文件。
- 小步迭代，一次一个明确目标，改完运行一次确认。
- 同一问题连续三次修不好，暂停局部修补，回头讨论设计。
- 修问题时不顺带重构无关代码。

## 5. 验收原则（用户 2026-10-26 要求简化）

每步只看**主目标大体能否印证**：能跑、结果方向和量级说得通、能看到想看的现象即可。不设百分比误差门槛，不做全覆盖测试，不加多层确认。看不懂的现象再查根因，未做的检查如实说明。

## 6. 与固件的边界

- 固件是被测对象。仿真工作默认**不修改**固件；确需修改（如计划 M2a 把 `compute_target()` 合成部分抽为 `App/control` 纯函数）时只做已批准的那一步，改完跑现有主机测试并确认固件仍能编译，不刷写。
- 不改 `Core/`、`Drivers/`、`.ioc`；不碰硬件、不烧录。
- 仿真发现的控制问题（如肩模型只含外骨骼自重）先报告，是否改控制设计由用户决定。

## 7. 目录与环境

| 位置 | 用途 |
|---|---|
| `AGENTS.md` | 本约定 |
| `README.md` | 环境搭建与运行命令 |
| `requirements.txt` | 固定版本的 Python 依赖（新依赖选发布满 7 天的版本） |
| `scripts/` | 冒烟、检查、构建桥接等小脚本 |
| `model/` | `params.json` 与模型生成脚本`build_model.py`（M1b） |
| `model/orthoease/` | 用户 Fusion 导出的外骨骼包（2026-10-27），**只读副本**；改动一律写在`build_model.py`里，Fusion 重新导出时整体替换此目录 |
| `bridge/` | 调用固件控制代码的 C 桥接（M2b） |
| `sim/` | Python 仿真模块（M3–M4） |
| `../../build/sim-venv/` | 虚拟环境（已被固件 `.gitignore` 忽略） |
| `../../build/sim-tmp/` | pip 缓存与临时文件 |
| `../../build/sim/`、`../../build/sim-runs/` | 生成的模型、DLL、实验结果 |

- **H 盘规则**（根 AGENTS 3.5）：本机 `TEMP/TMP` 默认在 C 盘。每次运行 pip、MSVC、仿真前，在命令里临时设置 `TEMP`、`TMP`、`PIP_CACHE_DIR` 到 `../../build/sim-tmp/`，不改系统环境变量。
- 固定 `mujoco==3.16.0`、Python 3.13（`H:\app\python.exe`）。升级前先说明原因。
- 生成物不提交；源码、参数、脚本提交。
