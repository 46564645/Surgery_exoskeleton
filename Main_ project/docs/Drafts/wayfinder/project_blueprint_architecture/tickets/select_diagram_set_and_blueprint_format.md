## Question

最终蓝图需要哪些关系图、表格和文字说明，才能让新会话或新开发者仅阅读蓝图就理解系统边界、模块职责、依赖方向和关键控制关系？

## Resolution

最终交付采用独立的`Main_ project/system_architecture_blueprint.md`，作为技术路线和系统架构的唯一权威文件。需求蓝图继续定义目标和优先级；硬件接口登记表继续定义设备端点与证据等级；本目录票据保存决策来源；旧技术文档只保留背景和历史内容，冲突时不得覆盖系统架构蓝图。

蓝图包含一张系统边界总览和四张同等深度的专业图：机械与物理架构、电气与通信架构、功能/控制/安全权限架构、嵌入式软件依赖架构。每个视图同时包含：可直接预览的SVG、生成SVG的Mermaid源、无需渲染即可阅读的文字关系图、逐条关系表、已确认边界和集中`TBD`。

五个SVG统一保存在`Main_ project/architecture_diagrams/`。图和文字使用相同的ExoKit语义关节名、`XDOM-*`接口编号、方向和验证状态。机械、能量、信息、控制权限和`TBD`使用不同线型、标签和颜色，但任何含义都不能只靠颜色表达。

26条跨域接口按专业视图分配：机械图承载`XDOM-MECH-01..05`；电气图承载`XDOM-ENERGY-01..06`及设备侧信息流；功能控制图承载统一状态、健康信息和`XDOM-CTRL-01..08`；软件图进一步表达这些逻辑合同在L4到L1中的所有权和不可绕过的依赖方向。

图形不是接线图、机械承载证明或人体安全结论。具体引脚、CAN字段、周期、阈值、增益、传动比、物理急停和人体连接继续保持`TBD`，受硬件接线门禁和后续台架验证约束。
