## Question

为了让机械、电气、控制和软件达到同等深度，同时避免一张关系图混合不同含义，最终蓝图应使用哪些互补架构视图？每个视图分别回答什么问题，哪些关系必须跨视图保持一致？

## Resolution

最终蓝图采用 Markdown 格式，面向 AI 直接读取。图形不是唯一信息来源；每个关系图中的模块、连接和方向都必须同时以 Markdown 标题、表格或关系清单表达，确保不渲染图形也能完整理解架构。

蓝图由一张低分辨率系统总览和四张同等深度的专业视图组成：

1. **系统总览**：说明用户、机械系统、电气系统、嵌入式控制系统和外部调试工具之间的总体边界。
2. **机械与物理架构视图**：说明人体连接、支撑结构、关节、执行器、运动关系和机械载荷路径。
3. **电气与通信架构视图**：说明电源、控制器、驱动器、电机、反馈来源和通信链路。
4. **功能与控制关系视图**：说明状态输入、持续重力补偿、动作放大、通电保持、输出合成、状态管理和安全控制权。
5. **嵌入式软件依赖视图**：说明 ExoKit 行为语义、应用与控制服务、关节抽象、设备适配和 STM32 HAL 之间的依赖方向。

所有视图必须遵守以下跨视图一致性规则：

- 同一模块在不同视图中使用相同的规范名称和模块标识。
- 每个机械执行器都能映射到对应的电气驱动路径、反馈来源和软件执行器适配模块。
- 每条状态或命令关系都明确来源、接收者和方向，不使用含义不明的双向箭头。
- 安全监督对最终输出的覆盖关系在控制视图和软件视图中保持一致。
- 尚未确定的传动、接线、参数或实现以“待决定接口”标记，不用假设补齐。
- 各专业视图深度一致，均说明模块职责、输入、输出、依赖、边界和未决事项，但模块数量不要求相同。
